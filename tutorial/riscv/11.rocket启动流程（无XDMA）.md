Rocket-chip 生成的 ExampleRocketSystem 是我们将采用的主要模块来构建我们的系统。它将 MIMO-AXI4 和 Mem-AXI4 接口暴露给外部外设，其中前者将连接到 IO 设备，包括 Uart（@0x60000000）、SD 插槽 （@0x60020000） 和 BRAM_64K（@0x60010000），后者将用于连接 DDR（@0x80000000） 存储器。
以下是 linux 启动过程的整个故事：
1. 开机后，根据变量Reset_Vector将PC（程序计数器）设置为0x10040。处理器开始在 ExampleRocketChip 内部的 TLBootrom（@0x10000） 中执行指令。TLBootrom 包含要求处理器跳转到BRAM_64K的说明：
	- `li s0, BRAM_BASE`,  `jr s0` ( /rocket-chip/bootrom.S )  
    `li s0, BRAM_BASE` ，  `jr s0` （ /rocket-chip/bootrom.S )
2. 在BRAM_64K中，我们完成了第一阶段引导加载程序（又名 FSBL）的两项任务：将包含 BBL（Berkeley 引导加载程序）和 vmlinux 映像的精灵映像复制到 DDR 中的特定地址 （@0x870000000），并将此精灵提取到 DDR（@0x80000000） 的开头。完成这两个任务后，FSBL 将跳转到 DDR，PC 将转到 bbl 程序：
	- `li s0, DDR_BASE`,  `jr s0` ( /firmware/head.S )  
    `li s0, DDR_BASE` 、  `jr s0` （ /firmware/head.S )
3. 在 DDR 中，BBL 会做一些准备工作，包括设置陷阱、SBI（主管二进制接口）和物理内存保护。然后将 DTB（设备树 blob）移交给内核（在早期版本中，BBL 还虚拟化内存，现在由 Linux 直接处理）。最终，BBL 启动 Linux 内核：
	- `enter_supervisor_mode(entry, hartid, dtb_output())` ( /riscv-pk/bbl/bbl.c )  
    `enter_supervisor_mode(entry, hartid, dtb_output())` （/riscv-pk/bbl/bbl.c）
5. 内核初始化后，busybox_init启动并调用busybox_ash，它为您提供了一个命令行界面。
# 参数说明
~~~ scala
class WithDefaultMemPort extends Config((site, here, up) => {
  case ExtMem => Some(MemoryPortParams(MasterPortParams(
                      base = x"10000_0000",
                      size = x"1000_0000",
                      beatBytes = site(MemoryBusKey).beatBytes,
                      idBits = 4), 1))
})
~~~
1. **base**：`base = x"10000_0000"` 定义了内存映射的基地址。这是外部内存映射到处理器地址空间的起始地址。这里使用的是16进制表示的地址，`0x10000000`。这个参数可以配合改变axi地址位宽
    
2. **size**：`size = x"1000_0000"` 定义了这块内存区域的大小，也是用16进制表示的。`0x10000000` 表示这块内存区域有256MB大小。
    
3. **beatBytes**：这个参数定义了每次内存交互传输的字节数。这个值是从系统的内存总线配置中获取的 (`site(MemoryBusKey).beatBytes`)，具体值取决于系统总线的配置。
    
4. **idBits**：`idBits = 4` 定义了事务标识符（Transaction Identifier，TID）的位数。这个位数决定了可以同时管理多少个独立的内存访问请求。4位可以表示最多16种不同的请求。
    

总结来说，这个类配置了系统的默认外部内存端口，指定了内存的基地址、大小、数据传输宽度和可以识别的独立内存请求的数量。这些设置对于设计内存管理和优化系统性能非常关键。
